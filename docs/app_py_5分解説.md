# 5分でわかる app.py：AIライティングツールの画面の仕組み

> 詳しい版は [app_py_解説.md](app_py_解説.md) を参照してください。

## まず押さえる「Streamlitのクセ」

Streamlit は、ボタンを押すなど**何か操作するたびに、スクリプトを上から全部実行し直します**。そのため、ふつうの変数は毎回消えてしまいます。

残しておきたいものは **`st.session_state`**（実行をまたいで中身が残る箱）に入れます。このアプリでは次のものを入れています。

- `page`：選んでいるツール
- `convo_ツールID`：AIとの会話（生成結果）
- `in_ツールID_項目名`：入力欄の値
- `pending_refine`：実行待ちの修正依頼

## ファイルの役割分担

| ファイル | 役割 |
|---|---|
| `app.py` | 画面と操作の流れ |
| `tools.py` | 各ツールのプロンプトと入力項目 |
| `gemini_client.py` | Gemini API との通信 |
| `history.py` | 履歴をJSONに保存 |

## コードの流れ

**1. 設定とキャッシュ**
`secret_api_key()` が、環境変数 → `secrets.toml` の順にAPIキーを探します。`@st.cache_resource` と `@st.cache_data` は、APIクライアントの作成やモデル一覧の取得を毎回やり直さないための仕組みです。

**2. サイドバー（`render_sidebar`）**
ツールのメニューは `tools.py` の `TOOLS` から自動で作られます。ツールを足すとメニューにも出てくるのはこのためです。モデルなどの設定はひとつの辞書にまとめて返します。

**3. 入力フォーム（`st.form`）**
フォームで囲むと、「生成する」を押すまで送信されません。入力中に画面が何度も再読み込みされるのを防げます。

**4. 生成（`generate`）** ← アプリの心臓部
1. `st.write_stream` で、Gemini の返答を届いた文字から順に表示する
2. 結果を `session_state` と履歴に保存する
3. `st.rerun()` で画面を描き直す

**5. 修正機能（コールバック）**
「もっと短く」を押すと、`on_click` に指定した関数が**再実行の前に**呼ばれ、「修正依頼あり」という**メモだけ**を残します。次の実行でそのメモを受け取り、これまでの会話に「もっと短く」を付け足して再生成します。

回り道をするのは、Streamlit では**描画済みのウィジェットの値を後から変更できない**からです。コールバックの中なら描画前なので安全に変更できます。

**6. 履歴ページ**
「ツールで開く」を押すと、以前の入力・出力・ページ選択を `session_state` に書き戻し、そのツールの画面を復元します。

**7. `main()`**
サイドバーを描いてから、選ばれたページを描きます。これが毎回の実行で走ります。

## まとめ：この3つだけ覚えればOK

1. **Streamlit はクリックのたびにスクリプト全体をやり直す**
2. **残したいものは `st.session_state` へ**
3. **ウィジェットの値はコールバックの中で変更する**
